# ADR-0002: Original binary and derived code stay out of the repository

- **Status:** accepted
- **Date:** 2026-11-17
- **Deciders:** project owner

## Context

The project statically recompiles the code of *Age of Empires II: The Conquerors*
(Microsoft / Ensemble Studios, 2000). That code and the game data are copyrighted.
Everything the recompiler produces from it (lifted C, disassembly dumps, Ghidra
databases, extracted function bytes) is a derivative of the original code.

The Phase 0 input is an `age2_x1.exe` that the owner built from their own retail
disc and patched themselves so it runs without the CD (a no-CD build). Its bytes
therefore differ from the retail executable at least where the CD check was
removed. See `docs/recon.md` for its hashes and what the recon found.

Static-recompilation projects that have stayed sustainable (N64Recomp-based ports,
XenonRecomp-based ports and others) follow the same rule: the repository holds
the *tools* and the *runtime*, and the user supplies their own copy of the game.

## Decision

1. Game binaries and data (`*.exe`, `*.dll`, `*.drs`, `*.dat`, ISOs, recorded games)
   are never committed. They live in `orig/` (git-ignored) or a path given by
   `AOE2_EXE`.
2. Anything generated from the binary's code goes under `build/` (git-ignored)
   and is regenerated by `make`. This covers lifted C, function byte extracts, Ghidra
   projects and full disassembly listings.
3. Documentation may contain addresses, counts, import names, small structural
   facts and short illustrative snippets of a few instructions. It never contains
   bulk disassembly or decompiled code.
4. CI that has no binary runs only tests on synthetic fixtures (code we wrote and
   compiled ourselves). Tests on the real binary run locally and skip cleanly
   when the binary is missing.
5. The project does not distribute or document how to remove copy protection.
   The recompiler consumes a binary the user already has in an executable form.

## Consequences

- Anyone building the port needs their own copy of the game. This is the expected
  model for a recomp port.
- Keep `make` deterministic so `build/` can be regenerated from the binary.
- The tools have to cope with byte-level differences between exe builds (retail,
  1.0c, no-CD builds), so they are keyed on hashes listed in `docs/recon.md`.
