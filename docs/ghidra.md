## Lift hazards

- **Self-modifying code:** Ghidra found 0 direct writes into executable sections. Indirect writes through computed pointers cannot be ruled out statically. The differential and runtime harnesses should check `.text` for integrity.
- **Data in code:** 28,059 items (53,838 bytes), mostly switch tables. MSVC6 places switch jump tables and byte-index tables right after the function. The lifter has to take them from Ghidra's analysis; a linear sweep would decode them as instructions.
- **Computed jumps:** 572 jumps, 556 with recovered tables (see above).
- **x87 FPU:** 963 functions (12.9%) use x87 instructions. Simulation code using floats is a determinism risk: lifted code must reproduce x87 results (80-bit intermediates, the precision-control word MSVC sets, `fistp` rounding) bit for bit, or multiplayer and recorded-game replays desync.
- **MMX:** 0 functions. **SSE:** 0 functions.
- **SEH:** 624 functions install an `fs:[0]` handler, either `_except_handler3` (C `__try`) or C++ EH through `__CxxFrameHandler`. Unwinding has to be modelled: either setjmp/longjmp-style unwinding in lifted code, or proof that the exceptions never fire in practice.
